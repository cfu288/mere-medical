# Git conventions

These rules apply to every commit, branch, and pull request made from an agent session, including cloud sessions.

- Commit messages follow Conventional Commits, for example `feat(web): show managing organization in tenant search results`.
- Commit messages and pull request bodies carry no attribution lines of any kind: no `Co-Authored-By`, no session links, no "Generated by" or "Generated with" footers. `.claude/settings.json` turns the built-in ones off; never add them by hand, and after opening or editing a pull request, read its body back and remove any footer a tool appended.
- Commits are authored by a person. If the configured git identity is `noreply@anthropic.com`, commit with `git -c user.name="Christopher Fu" -c user.email="invent288cfu@gmail.com"`.
- Branch names never contain the word "claude". Before the first push, move the work to a branch named `<type>/<short-slug>`, such as `feat/tenant-search-managing-org`, and push that branch. Never push a session's auto-created branch.
- Pull requests use the conventional commit as the title and have an empty description. Reference issues in the commit message, for example `Closes #434`, not in the PR body.
- Commit and push only when asked.
